# Training Bug: Repetitive Generation (`Lily Lily Lily...`)

> **Date:** 2026-08-29  
> **Notebook:** `self.ipynb`  
> **Dataset:** `roneneldan/TinyStories` (80k train / 5k val, streaming, 512 ctx, batch 4)  
> **Model:** GPT-2-style 162M (12 layers, 768 d_model, 12 heads, 3072 ff)

## Symptom

Training finished with impossibly low loss and collapsed generation at *every* checkpoint:

```
Epoch 1/1 | train loss: 0.0366 | val loss: 0.0087
--- Inference @ epoch 1 step 2,000 ---
Once upon a time there was a little girl named Lily Lily Lily Lily Lily ...
--- Inference @ epoch 1 step 4,000 ---
Once upon a time there was a little girl named Lily Lily Lily Lily ...
--- Inference @ epoch 1 step 8,000 ---
Once upon a time there was a little girl named Lily Lily Lily Lily ...

-- greedy (temp=0) --   Lily Lily Lily ...
-- creative (temp=0.8) -- Lily Lily Lily ...
-- more random (temp=1.2) -- gibberish fragments
```

Repetition was **not** fixed by more steps, higher `temperature`, or `top_k`. `val < train` and `ppl = exp(0.03) ~ 1.03` (a true LM should have `loss ~ 2-4`, `ppl ~ 7-50`).

## Root Cause: Missing Next-Token Shift (Copy Task)

### 1. Dataset returned identical `input_ids` and `labels`

```python
# cell dataload-4-dataset — BUG
class LMDataset(Dataset):
    def __getitem__(self, idx):
        ids = torch.tensor(self.chunks[idx], dtype=torch.long)
        return {"input_ids": ids, "labels": ids.clone()}  # <-- same 512 tokens
```

### 2. Loss compared logits at position `i` against label at `i`

```python
# cell train-2-loop — BUG (train + val loops)
logits = model(input_ids)  # (B, T, V) ; causal mask sees t_i at position i
loss = criterion(logits.view(-1, V), labels.view(-1))  # predicts t_i | t_<=i
```

With `is_causal=True` the model at position `i` already sees `t_i`, so predicting `t_i` is a trivial **copy**. The network learns `output = last_token` in <2k steps, loss → 0, and autoregressively repeats that token forever. Greedy `argmax` in `generate_preview()` made collapse deterministic; sampling could not rescue a delta distribution.

### 3. Secondary issues

* `GPT.forward`: `x + positional_embedding(positions)` relies on implicit broadcasting `(T,D)+(B,T,D)`. Works but fragile — should be `.unsqueeze(0)`.
* No `clip_grad_norm_` — 162M model unstable without clipping.
* `MultiHeadAttention` defaults `q_dim=384, v_dim=420` → head dims 32 vs 35 (asymmetric). Not used in `GPT(q=768,v=768)` run but misleading.

## Fix Applied (2026-08-29)

### A. Shifted next-token objective — predict `t+1` from `t`

Keep dataset length at 512 (no data change) and shift **in the loss** (most explicit, matches HF `transformers`):

```python
# train loop
logits = model(input_ids)  # (B, T, V)
# shift: logits[ :, :-1] predicts labels[ :, 1: ]
loss = criterion(
    logits[:, :-1].contiguous().view(-1, logits.size(-1)),
    labels[:, 1:].contiguous().view(-1)
)

# val loop — identical shift
logits = model(input_ids)
loss = criterion(
    logits[:, :-1].contiguous().view(-1, logits.size(-1)),
    labels[:, 1:].contiguous().view(-1)
)
```

Alternative (equivalent) is to shift in `Dataset`:

```python
def __getitem__(self, idx):
    ids = torch.tensor(self.chunks[idx], dtype=torch.long)
    return {"input_ids": ids[:-1], "labels": ids[1:]}  # 511 tokens, x=t0..T-2 y=t1..T-1
```

### B. Positional embedding

```python
# GPT.forward — before
x = x + self.positional_embedding(positions)
# after
x = x + self.positional_embedding(positions).unsqueeze(0)  # (1,T,D) -> (B,T,D)
```

### C. Gradient clipping

```python
loss.backward()
torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
optimizer.step()
```

### D. Checkpoint invalidation

The saved weights `gpt_tinystories.pt` / `gpt_tinystories_ckpt.pt` learned the copy task and must **not** be resumed:

```bash
rm gpt_tinystories.pt gpt_tinystories_ckpt.pt
```

Training restarted from random init with `EPOCHS=1`.

## Prevention

* Unit test: `assert not torch.equal(batch["input_ids"], batch["labels"])` or check `labels[:,0] != input_ids[:,0]`.
* Assert loss at step 10 > 3.0 — fail fast if shift missing.
* Add `perplexity = exp(loss)` to logs.
